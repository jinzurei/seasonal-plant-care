2. Submission Notes:

This program is a seasonal plant care assistant that pulls from a curated plant database and gives users adaptive care recommendations based on the current time of year. The idea was to build something clean and simple on the surface, but flexible and genuinely helpful under the hood the kind of thing someone might actually use, not just a proof of concept.

The CSV file might look basic, but it's not. Every plant entry was hand-written and cross-referenced with actual care guides, then rewritten to match a seasonal format. Each plant has unique advice and individual spring/summer/fall/winter care notes not just repeated filler. Categories, traits, and terminology were also standardized manually so the search tool could work reliably. It took time to balance it all so that it would stay readable in the console, while still being useful and accurate. A lot of care went into making the data both functional and clean.

The main program brings all of that together and wraps it in a structured menu with seasonal logic. It detects the current date and dynamically pulls the right care advice. Users can either:
- Look up any plant by name
- Or run a general search based on traits, lighting, water needs, or even partial matches

The search logic isn’t just basic string matching. It normalizes input and checks across the plant's name, category, and trait fields and can handle multi-word input like “low light succulent vine.” The goal was to make the experience intuitive, even if the user doesn’t remember the exact plant name. Results come back as a numbered list, and users can select one to get a full breakdown of that plant's info for the current season.

And then there’s the test program. This part went way beyond basic unit testing. It dynamically selects a random plant from the CSV, then tests multiple conditions:
- Whether that plant can be found by its exact name
- Whether any of its traits can be used to locate it
- Whether a partial version of one of its traits still matches
- Whether nonsense input returns nothing

Each test prints out progress along the way including which plant was selected, what trait was tested, how many matches came back, and emoji feedback to keep it clear. It’s easy to run and understand, and it helps verify that the search tool performs consistently no matter what data is used.

The "pyproject.toml" file makes sure all the print output displays correctly during pytest without needing to manually pass "-s", which is great for future portability or grading. Everything is done using Python’s built-in modules no external libraries were needed. The program is light, flexible, and designed to be expanded later (like adding a GUI or saving plant care logs).

In short, this is more than just a working program it’s something that shows planning, polish, and care in all parts of the design, creating a dynamic search tool.
